# ADR-0007: リソース失敗を必須/任意に分けて安全に扱う

- Status: Accepted
- Implementation: Done

## 背景
Audio、WIC、Direct3Dなどの初期化・読み込み処理に、ファイル操作やAPI呼び出しの失敗を十分に検査しない経路がある。例えば`Engine/Audio.cpp`はファイル読込結果を検証せずWAVチャンクを検索し、`Engine/Direct3D.cpp`はシェーダーコンパイル結果を確認せず後続処理へ進む箇所がある。

## 決定
必須リソースの初期化・読み込みに失敗した場合は、診断情報を示して安全に起動またはシーン生成を失敗させる。任意リソースの失敗は記録し、安全な代替表示・動作へ切り替える。

## 影響
- 各リソースを必須/任意に分類する。
- 読込APIは失敗を呼び出し元へ伝え、部分初期化時も安全に解放できるようにする。
- 診断の具体的な出力先や代替表現は、実装時にリソースごとに決める。

## 実装時の決定
実装時に決めた分類と動きを記録する。

### 分類
| 分類 | リソース | 失敗したとき |
|------|----------|--------------|
| 必須 | Assetsフォルダ、COM、ウィンドウ、Direct3D（デバイス・シェーダー）、ImGui、DirectInput、XAudio2、3Dモデル | 原因を示すダイアログを出して終了する（終了コード1） |
| 任意 | 画像（UI・フォント）、音声ファイル、テクスチャ（FBX・パーティクル）、デバッグ表示用のコライダのモデル、設定ファイル（INI） | 警告を記録して続行する |

### 診断の出力
- 診断は`Debug`モジュールが受け持つ。`Debug::Warning`は任意リソースの失敗を、`Debug::Fatal`は必須リソースの失敗を記録する。
- どちらも、出力ウィンドウ（`OutputDebugString`）と、exeと同じ場所の`Log.txt`（UTF-8、起動ごとに上書き）に書く。ログファイルを書けなくても、ゲームは続行する。
- ダイアログは必須リソースの失敗のときだけ、`Main`が処理を終えたあとに一度出す。同じ内容は重複させない。

### 失敗したときの動き
- 起動時（COM、ウィンドウ、Direct3D、シェーダー、ImGui、入力、音声エンジン）: 失敗したらそこで中断し、できたものだけを解放して終了する。
- シーン生成中（モデルの読み込みなど）: 失敗を記録して処理は続け、`Main`が次の周回で検知して、描画せずに終了する。読み込めなかったモデルは番号が-1になるが、`Model`の各関数は無効な番号を渡されても落ちない。
- 任意リソースの代替: 画像は128×128のマゼンタの代替画像（`Image::Load`は有効な番号を返す）。音声は鳴らさない（`Audio::Load`は-1を返し、`Play` / `Stop`は何もしない）。FBXのテクスチャは無地（マテリアルの色）。パーティクルの画像は表示しない。
- 読み込み側で失敗を扱うようにしたため、読み込んだ番号を確かめる`assert`は取り除いた。

### 持ち越していた項目
- COM初期化は`Main`が起動時に一度行い、終了時に解放する。`Audio`と`Texture`は初期化しない（ADR-0004の残課題）。
- `Audio::Load`は、チャンクをたどって`fmt`と`data`を探す形に作り直した。ファイルの終わりでも抜けない読み方と、読み飛ばしたチャンクのバッファの解放漏れをなくし、ファイルが無い・壊れている場合は警告を記録して-1を返す。
- `Audio::Initialize()`の失敗は必須として扱い、`Main`が戻り値を見て終了する。

### 実装中に見つかった既存の問題（今回は直していない）
- `Direct3D::Initialize`の深度ステンシルステート（通常）は、ステンシルの設定が足りず作成に失敗し続けている。`nullptr`のまま、既定の状態で描画されている。直すと深度の書き込みが変わって描画結果が変わるため、警告に残して従来どおり続行している。
- `Input::Initialize`のキーボードの協調レベル設定は、ウィンドウハンドルにNULLを渡しているため失敗している。従来どおり続行し、警告に残している。
- 上の2件は、正常に起動しても`Log.txt`に毎回警告として残る。
- `PlayerBase.cpp`が`WalkOrFight`を読む`Setting/PlayScene.ini`は存在しない（実在するのは`PlaySceneSetting.ini`）。そのため、この値は常に既定値の0になる。
- `FrameBox`は`DebugCollision/BoxCollider.fbx`を、デバッグ表示ではなくゲーム内のモデルとして読み込んでいる。そのため、このファイルは必須として扱っている。
