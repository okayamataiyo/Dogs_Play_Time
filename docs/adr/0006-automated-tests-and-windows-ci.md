# ADR-0006: 自動テストとWindows x64ビルドCIを導入する

- Status: Accepted
- Implementation: In progress

## 背景
現在のVisual Studioプロジェクト探索では、専用テストプロジェクトやCI設定を確認できなかった。対象プラットフォームはWindows x64であり、ゲームのロジックとDirect3D等のOS依存処理を分けて検証する必要がある。

## 決定
自動テストを導入し、Windows x64のDebug/ReleaseビルドをCIで確認する。まずはグラフィックス初期化に依存しないロジックをテスト対象とする。

## 影響
- テスト可能なロジックとプラットフォーム依存処理の境界を明確にする。
- CI提供者、テストフレームワーク、具体的なテスト範囲は実装時に選定する。
- 現在のローカル環境ではv143ツールセット不足によりビルド確認できなかったため、CI/開発環境で必要ツールセットを明示する。

## 実装時の決定
実装時に決めた内容と、確かめたことを記録する。

### 構成
- テストの枠組みはdoctest（v2.5.3、MITライセンス）。`Tests/third_party/doctest/`にヘッダー1つをそのまま置いた。追加の取得手順がなく、CIも実行ファイルを走らせるだけで済む。
- `Tests/`に新しいプロジェクト`Dogs_Play_Time.Tests.vcxproj`を作り、ソリューションに加えた。ゲーム本体のソースは静的ライブラリに分けず、確かめたいものだけをそのままコンパイルして使う。ゲーム本体のプロジェクトとは独立していて、FBX SDKもDirect3Dの初期化も要らない。
- `Model`と`Direct3D`の関数のうち、テスト対象が呼ぶもの（`Model::Load`・`Draw`・`SetTransform`、`Direct3D::SetShader`・`GetViewPort`と2つの変数）は、`Tests/Stubs.cpp`のダミーに差し替えてリンクする。
- 既存のソースはShift-JISなので、テストのビルドには`/source-charset:.932 /execution-charset:.932`を付け、実行する環境の言語設定に左右されないようにした。
- ツールセットはv145（VS 2026）に固定した。v143は、ローカル環境にも、CIのランナー（`windows-2025`はv145のみ）にもない。VS 2022でビルドするときは手元だけで変える。必要な環境と手順は`docs/build.md`にまとめた。

### テストできるようにした境界
- `Model.h`が`Fbx.h`（さらに`fbxsdk.h`）を読み込んでいたため、`Model.h`を使う当たり判定や`GameObject`は、FBX SDKなしではコンパイルできなかった。`RayCastData`を`RayCastData.h`へ移し、`Fbx`は前方宣言にした。動作は変わらない。
- `Audio::Load`のWAV解析を、メモリ上のバイト列だけを見る`WavParser::Parse`に切り出した。ファイルを全部読んでから解析する形になった。13ファイルの波形データのSHA-256が、独立に求めた正解と一致すること、壊れたWAVで従来どおりの警告・`-1`・正常終了になることを確かめた。

### CI
- GitHub Actions（`.github/workflows/ci.yml`）。push・プルリクエスト・手動で動き、`windows-2025`（VS 2026）でテストをDebugとReleaseの両方でビルドして実行する。同じブランチで新しい実行が始まったら古い実行は止める。使うアクションは、コミットのハッシュで固定した。
- ゲーム本体はCIの対象外にした。FBX SDKは同梱できず、クラウドのランナーにも入れられないとライセンス本文から読めるため（ADR-0005）。本体のビルドは手元で確認する。

### テストの範囲
`CsvReader`、`JsonReader`、`Debug`、`Transform`、`StateManager`、当たり判定（箱・球体）、`GameObject`（親子、更新・描画・解放の順序、コライダーの解放、検索）、`WavParser`。実装時点で54件・246の検証。ADR-0003で所有権を変えるときに、順序が変わらないことを確かめるためのテストを含む。

今の動きをそのまま確かめるテストで、次のような癖もそのまま固定している。直すときはテストも直すこと。
- `GameObject::GetWorldPosition`は、親の位置だけを足す（親の親は足さない）。
- 箱と球体の判定は、箱を半径だけ広げた箱で調べるので、角の外側でも当たる。

### 確かめたこと
- テストのDebug・Releaseのビルドと全件合格。コミット済みの内容だけをクローンして、ワークフローと同じコマンドで確かめた。
- テストが壊れ方を検出できること。製品コードを少しだけ壊したコピーで確かめ（14通り）、すべてテストが失敗した。
- ゲーム本体のDebug・Releaseのビルドと起動、WAVの読み込み結果（上記）。
- ワークフローの構文（actionlint）。

### 確かめていないこと
- GitHub上での実行（pushして確かめる）。`windows-2025`にv145とWindows SDKがあることは、リリースノートからの想定。
- 実際に遊んでの確認（タイトルから対戦、音、UI）。

### 持ち越し・見つけた既存の問題（今回は直していない）
- ゲーム本体のCIビルド。FBX SDKの許諾が確認できるまで対象外（ADR-0005）。このため`Implementation`はIn progressのまま。
- 他のロジック（AIのビヘイビアツリー、Input、Imageなど）のテストと、Engineの静的ライブラリへの分割。
- `CsvReader`は、改行がLFだけのファイルでは1行も読めず、最後がCRLFで終わらないファイルでは最後の行を落とす。ゲーム側から`CsvReader`を使っている所は、今はない。
- `GameObject::UpdateSub`の`Transform();`は、一時オブジェクトを作って捨てるだけの文になっている。
- `GameObject::KillObjectSub`は、引数の`obj`ではなく自分の`childList_`が空かどうかを見ている（`KillAllChildren`から呼ぶときは自分の一覧が空でないので、結果には出ない）。
